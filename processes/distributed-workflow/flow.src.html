Lanes

Every workstream tracker, its phases, and what each one is waiting on — parsed from the tracker files, not typed. Fifteen files and 136,000 words reduced to the only question that matters at the start of a session: what can be worked on right now, and what is blocked on a person?

What is live

A lane is live when its tracker carries a boot prompt marked ACTIVE. More than one is normal here — they are different lanes, not drift — but a session must be told which, never guess.

What is blocked, and on whom

A gate on a person cannot be cleared by any amount of work. It is the only category worth surfacing above everything else.

How the trackers depend on each other

An edge is one tracker citing another. Thickness is not encoded; position is — trackers are ordered by how many others point at them, so the load-bearing ones sit at the top.

Phases with no readable state

These boot prompts carry no status marker the parser can read, so their state exists only in prose — which is exactly how a stale lane survives unnoticed. Some are heading-format variance rather than genuinely unmarked; either way the state is not machine-readable.
